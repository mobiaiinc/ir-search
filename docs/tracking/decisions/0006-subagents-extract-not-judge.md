# 0006 — 서브에이전트는 추출·검수만 하고 판정은 상위 에이전트가 한다

## 맥락
후보가 15건을 넘으면 상세 원문 30개를 한 컨텍스트에서 읽기 어렵다. v2 SKILL.md는 "서브에이전트에게 구조화 추출을 위임"이라고만 했고 정의가 없었다. 위임 범위를 어디까지로 할지 — 추출만인지, A/B/C 판정까지인지 — 정해야 했다.

## 결정
- `ir-detail-verifier`: 원문 → 필드 + 근거 인용. 프로필은 참고만 하고 판정하지 않는다
- `ir-report-reviewer`: 보고서 ↔ 원문 ↔ 큐 대조. 고치지 않고 실패 목록만 낸다
- 판정(A/B/C)과 프레이밍 각도(C)는 상위 에이전트가 프로필과 사용자 대화 맥락을 갖고 직접 한다

## 대안
- 판정까지 위임: 서브에이전트는 사용자와의 대화(이전 기각 사유, 이전 가능 지역의 뉘앙스)를 모른다. 판정이 갈리면 근거를 다시 읽어야 해 위임 이득이 사라진다
- 검수 에이전트가 직접 수정: 수정과 검수가 한 주체면 검수가 아니다. 또 수정하려면 판정 맥락이 필요해 위 문제로 돌아간다
- 소스별로 에이전트 분리(K-Startup 전용 등): 원문 텍스트 형식이 같아(첫 줄 URL + 본문) 나눌 이유가 없다

## 결과
- `verified.jsonl`의 각 값에는 근거 인용이 있어야 하고, 없으면 불명이다 (검수 에이전트가 이를 확인)
- 두 에이전트는 네트워크 도구를 갖지 않는다. 추가 수집은 상위 에이전트가 한다
- 15건 기준은 경험값이다. 바꾸려면 SKILL.md 3단계와 에이전트 description 둘 다 고친다
