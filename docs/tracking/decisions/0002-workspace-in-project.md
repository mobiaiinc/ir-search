# 0002 — 조사 상태를 프로젝트의 `.ir-search/`에 둔다

## 맥락
v2는 보고서를 `~/Documents/지원사업조사_<대상>_<날짜>/`에 쓰고 프로필만 프로젝트 루트의 `ir-search-profile.md`에 두었다. 재조사(diff)는 프로필의 "마지막 조사" 줄에 적힌 경로로 직전 폴더를 찾았다. 한 세션을 넘기는 조사(후보 30건 검증)에서 끊기면 어디까지 했는지 알 길이 없었고, 프로젝트를 다른 기기로 옮기면 `~/Documents`가 따라가지 않았다.

## 결정
모든 상태(프로필·워크로그·큐·결정·실행 폴더)를 `<project>/.ir-search/`에 둔다. 보고서도 실행 폴더 안이다. 사용자가 `~/Documents`에도 원하면 복사본이다. 레거시 `ir-search-profile.md`는 `init`이 이관한다.

## 대안
- `~/Documents` 유지 + 프로젝트에 포인터만: 기기 간 이동·팀 공유가 안 되고, `.gitignore` 한 줄로 커밋 여부를 정할 수 없다
- `~/.claude/ir-search/<프로젝트 해시>/`: 사용자 눈에 안 보여 "지난번 보고서 어디 있지"가 반복된다
- 프로젝트 루트에 `ir-search/` (점 없이): 소스 트리를 어지럽히고 빌드 도구가 긁어갈 수 있다

## 결과
- `.ir-search/`는 프로젝트가 git에 넣을지 정한다. `details/`는 크므로 보통 제외
- diff 베이스라인은 `run last`가 주는 실행 폴더이지 프로필의 경로 문자열이 아니다
- 이 저장소 자체의 `.gitignore`에 `.ir-search/`를 넣어 개발 중 워크스페이스가 섞이지 않게 한다
