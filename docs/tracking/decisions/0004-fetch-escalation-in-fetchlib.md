# 0004 — 차단 에스컬레이션을 공용 모듈이 자동 수행

## 맥락
v2의 `references/sources.md`에는 차단 시 사다리(safari → safari_ios → chrome → chrome_android → 모바일 호스트 → 포기)가 **사람·모델이 따라 할 절차**로 적혀 있었고, 크롤러 두 개가 각각 `make_fetcher`와 `time.sleep`을 갖고 있었다. 모델이 사다리를 수동으로 타려면 스크립트를 고쳐 재실행해야 했다.

## 결정
`fetchlib.Fetcher`가 요청마다 사다리를 자동으로 탄다. 차단 판정은 상태 코드와 본문 마커 둘 다. 사다리 끝에서는 `Blocked` 예외를 올리고, 크롤러는 그 소스를 "차단"으로 보고하며 종료 코드 2. 지연·재시도도 여기로 옮겼다.

## 대안
- 절차를 문서로만 유지: 모델이 매번 스크립트를 수정해야 하고, 결과가 일관되지 않는다
- 사다리 순서를 CLI 옵션으로: 옵션이 늘고 모델이 고를 근거가 없다. 순서는 실측으로 정해진 것이라 상수가 맞다
- 차단 시 자동으로 브라우저 자동화로 넘어가기: "우회하지 않는다" 정책과 충돌. 브라우저 폴백은 사람이 결정한다

## 결과
- 크롤러에서 직접 HTTP를 하면 안 된다 (standards)
- 마커 목록(`BLOCK_MARKERS`)이 정상 페이지에 오탐하면 수집이 줄어든다 — 실측으로 조정해야 하고, 그것이 findings 1번
- 지문은 세션 안에서 끈적이므로 소스별로 초기화가 필요하면 `Fetcher`를 새로 만든다
