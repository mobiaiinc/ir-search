# 0003 — 큐는 JSONL + 스크립트, 워크로그·결정은 append-only 마크다운

## 맥락
체크포인트(후보 → 검증 대기)와 사용자 액션(신청·유선확인·재조사)을 한 곳에서 추적해야 했다. 사람이 읽는 것과 스크립트가 D-day를 계산하고 자동 종료하는 것 사이에서 형식을 골라야 했다.

## 결정
- `queue.jsonl`: 기계가 읽고 쓴다. 보기는 `queue list`가 마크다운 표로 렌더링
- `worklog.md`, `decisions.md`: 사람이 읽는 마크다운, 스크립트는 끝에 추가만
- `profile.md`: 사람이 편집하는 마크다운, 스크립트는 `마지막 조사` 줄만 치환

## 대안
- 전부 마크다운 (큐도 표): 마감 정렬·D-day·자동 종료를 하려면 표를 파싱해야 하고, 사람이 셀을 조금만 바꿔도 깨진다
- 전부 JSON 한 파일(`state.json`): 워크로그·결정이 diff에서 읽기 어렵고, 사람이 결정 이유를 길게 적을 자리가 없다
- SQLite: 의존성은 없지만 `cat`으로 못 보고 git diff가 무의미해진다

## 결과
- 큐 필드는 추가만 가능 (호환 규칙). 사용자의 다른 프로젝트 큐 형식에 맞출 때도 필드 추가로 한다
- 워크로그의 잘못된 항목은 고치지 않고 다음 항목 메모로 정정한다
- 큐를 사람이 손으로 고치면 JSONL 한 줄 규칙을 지켜야 한다 — 대신 `queue done`을 쓰라고 안내
