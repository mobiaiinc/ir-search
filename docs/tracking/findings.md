# 미해결 문제

지금 못 푸는 것만. 각 항목은 "조건 → 증상 → 영향 → 왜 지금 못 푸나 → 가능한 접근".

## 1. fetchlib의 실사이트 동작이 미검증

- **조건**: v3.0.0에서 두 크롤러의 HTTP 경로를 `fetchlib.Fetcher`로 교체함
- **증상**: 개발 환경이 `www.k-startup.go.kr:443` 등으로의 CONNECT를 거부해 실제 응답으로 사다리·차단 판정을 확인하지 못함. 가짜 백엔드 테스트만 통과
- **영향**: 실사이트에서 curl_cffi 세션 재생성(`rotate`)이나 마커 오탐(정상 페이지에 "captcha" 문자열이 있는 경우)이 있으면 수집이 조용히 줄 수 있음. 단, 파싱 0건 경고와 종료 코드 2가 있어 완전한 침묵은 아님
- **왜 지금 못 푸나**: 네트워크 정책. 코드로 우회하지 않음
- **접근**: 네트워크 있는 곳에서 `python3 scripts/sources_crawl.py list all -o /tmp/s.jsonl --max-pages 2` 실행 후 stderr 확인. 마커 오탐이 나오면 `BLOCK_MARKERS`를 `<title>`·첫 1KB로 좁힌다

## 2. 한 사업이 두 소스에 있을 때의 중복은 코드가 모른다

- **조건**: 같은 지원사업이 K-Startup과 기업마당에 동시 게재
- **증상**: jsonl에 두 레코드로 남고 diff도 각각 추적. 합치는 것은 모델이 보고서 단계에서 제목 유사도로 함
- **영향**: diff 모드에서 한쪽 소스에서만 마감이 갱신되면 "마감 변경"과 "변경 없음"이 동시에 나올 수 있음
- **왜 지금 못 푸나**: 제목 정규화만으로는 오합병 위험이 크고(같은 기관의 연도별·권역별 유사 제목), 공고번호는 소스마다 다름. 사람의 판단이 더 정확한 영역
- **접근**: 모델이 합친 결과를 `decisions.md`가 아니라 `runs/<날짜>/merged.jsonl` 같은 파생 파일에 남기고 다음 diff가 그것을 힌트로 쓰는 방식. 파생 파일은 `diff_surveys.SKIP_FILES`에 추가해야 함
