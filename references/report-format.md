# 보고서 형식과 검증 항목

`$RUN/report.md`의 구조와, 3단계 상세 검증에서 각 공고마다 확인해야 하는 항목. SKILL.md의 4단계가 이 파일을 따른다.

## 검증 항목 (공고 1건당)

상세공고 원문(`details/*.txt`)에서 아래를 확인한다. **원문에 없는 항목은 '불명'으로 적는다** — 제목·카테고리·상식으로 채우지 않는다.

| 항목 | 확인할 것 | 함정 |
|---|---|---|
| 신청대상 | 예비창업자 가능 여부가 **문구로** 있는가 ("예비창업자 포함/및", 예비용 별도 서식) | 사업자등록증·4대보험 명부·재무제표 요구 = 사실상 기창업만. 청년 요건은 만 나이 기준일(공고일/접수마감일) 확인 |
| 지역제한 | **소재 요건**(사업장이 어디 있어야 하나)과 **접수 자격**(누가 접수할 수 있나)을 구분 | "전국 접수, 비수도권 소재만" 같은 조합. "○○ 소재 또는 이전 예정" 문구는 B그룹 트리거 |
| 지원내용 | 금액·공간 조건·기간을 **구체 수치**로 | "최대 N억"은 최대치일 뿐. 자부담 비율·현물 요건 병기 |
| 제외 요건 | 타 사업 중복수혜 금지, 특정 프로그램 수료자 제외, 업종 제한 | 사용자가 이미 받은 지원과 충돌하는지 프로필과 대조 |
| 실적 요건 | 투자유치·매출·고용 등 트리거 조건 | B그룹 로드맵의 재료 |
| 마감 | 날짜 + **시각** (14:00, 16:00, 18:00 마감이 흔함) | "D-1"이어도 당일 오전 마감일 수 있음. 온라인 접수 시스템 점검 시간 |
| 문의처 | 전화·이메일 | 불명 항목이 하나라도 있으면 보고서에 문의처를 반드시 병기 |
| 본문 위치 | 본문이 첨부(HWP/PDF)뿐인가 | 그 경우 "본문은 첨부 참조"로 적고, 위 항목은 요약 필드에서 확인된 것만 |

서브에이전트(`ir-detail-verifier`)에게 위임하면 위 항목이 `verified.jsonl`의 필드가 된다. 각 필드에 **근거 인용(원문 문장)**을 붙이게 한다 — 인용 없는 "가능"은 추정이다.

## 판정 기준 (A / B / C)

- **A** — 프로필의 창업 단계·소재·대표자 특성 그대로 신청대상에 들어가고, 제외 요건에 걸리지 않으며, 마감이 지나지 않음. 하나라도 '불명'이면 A로 두되 "유선확인 필요"를 붙인다 (불명 때문에 B로 내리지 않는다 — 기회를 숨기는 쪽이 더 나쁜 오류)
- **B** — 현재는 자격 미달이지만 트리거(법인 설립 / 투자유치 / 지역 이전 / 매출 실적)가 공고에 명시됨. 트리거를 문장으로 쓰고, 트리거끼리 연쇄되면(경진대회 상금 → 법인 → 프리팁스 → TIPS) 경로로 그린다
- **C** — 신청대상 자체는 맞지만 사업 취지가 아이템과 다름. 아이템을 그 분야 언어로 재서술하는 각도를 **구체 문장**으로 제안하고, 리스크(결과물 요건, 지역 충돌, 서류)를 적는다. 각도가 안 떠오르면 C가 아니라 탈락이다
- **탈락** — 보고서 본문에는 안 넣되, 사용자가 물어볼 법한 유명 사업이면 "부재 확인"이나 "검토했으나 제외" 목록에 URL과 한 줄 이유로 남긴다

판정에 트레이드오프가 있었으면 `survey_state.py decide`로 기록한다.

## 전수 보고서 (full 모드)

```markdown
# 지원사업 전수조사 — <대상> (<아이템 한 줄>, <창업 단계>, <지역>)
조사일 <YYYY-MM-DD> · <소스별 건수> 전수 검토 → 후보 <N>건 상세 검증
실행 폴더: .ir-search/runs/<날짜>/ · 프로필: .ir-search/profile.md

## A그룹 — 지금 즉시 지원 가능 (마감순)

1. **<공고 제목>** — <기관>
   - 지원: <금액/공간/기간 — 원문 수치>
   - 자격: 예비창업자 <✓/불명> · <연령/성별/소속 요건> · <지역 요건>
   - 제외/주의: <중복수혜 등, 없으면 "확인된 것 없음">
   - 마감: <YYYY-MM-DD HH:MM> (D-N) <⚠️ 임박 if ≤3일>
   - 문의: <전화/이메일>   ← 불명 항목이 있을 때 필수
   - <원문 URL>

## B그룹 — 요건 충족 시 열림 (로드맵)

- **<공고 제목>**: 트리거 = <무엇>. 연쇄 경로: <A → B → C>
  - <원문 URL>

## C그룹 — 변형(프레이밍)하면 가능

- **<공고 제목> (<기관>)**: "<현재 서술>"이 아니라 "<재서술>"로 제출하면 대상. 리스크: <...>
  - <원문 URL>

## 보조: 공간 옵션 비교 / 상시·무료 인프라
(해당 시. 각 항목 URL)

## 부재 확인
- <유명 사업>: 현재 모집중 아님 (통상 <시기> 공고 — 재조사 큐에 등록)

## 검토했으나 제외 (선택)
- <제목> — <한 줄 이유> — <URL>

## 우선순위 액션
- ~<M/D>: <A-1 신청 (마감 시각 주의)>
- ~<M/D>: <C-1 프레이밍 초안 → 문의처 유선확인>

## 한계 고지
- 상세 검증 범위: <N>건 / 전체 <M>건 (나머지는 제목·카테고리 기준 제외)
- '예비 가능' 판정은 공고 텍스트 기준 — 신청 전 접수기관 유선확인 권장
- 마감 연장·조기마감 가능성. 소스 <X>는 차단/JS 로딩으로 미수집 → 수동 확인 (큐 참조)
- 조사 시점의 공고 상태이며, 이후 변경은 반영되지 않음
```

```markdown
## 신규 공고 (<N>건) — A / B / C 분류
(전수 보고서와 같은 항목 형식)

## 마감 변경 (<N>건)
- **<제목>**: <이전 마감> → <새 마감>. 판정 유지 (<A/B/C>) <· 자격요건 재확인 결과>

## 종료된 기회 (직전 A그룹 / 큐의 신청 진행 중)

- <제목> — 마감 <날짜> (D-N) — <URL>

(전수 보고서와 동일)
```

## 공통 규칙

- **모든 공고에 원문 URL** — 핵심 추천뿐 아니라 보조·탈락·부재 섹션까지. 공고번호만 적으면 사용자가 찾을 수 없다. K-Startup은 `https://www.k-startup.go.kr/web/contents/bizpbanc-ongoing.do?schM=view&pbancSn={공고번호}`, 그 외 소스는 jsonl의 `url` 필드
- 마감일·금액·요건은 원문에서 확인한 것만 기재. 추정 금지. 불명은 불명이라 쓰고 문의처 병기
- 같은 사업이 두 소스에 있으면 한 항목으로 합치고 소스를 병기한다
- 채팅 응답은 사용자가 요청한 형식을 따르되, 기본은 표 없는 텍스트 + URL 명시. 응답 끝에 `queue list` 출력을 붙인다
- 보고서에 개인정보(주민번호·계좌 등)를 넣지 않는다

## 검수 체크리스트 (`ir-report-reviewer`가 사용)

- [ ] 언급된 모든 공고에 URL이 있다 (부재/제외 섹션 포함)
- [ ] A그룹 각 건의 `details/`에 원문 파일이 있다 (없으면 검증 안 된 것)
- [ ] 보고서의 금액·마감·요건 수치가 `details/` 원문에 나온다 (원문에 없는 수치 = 추정)
- [ ] 불명 항목이 있는 건에 문의처가 있다
- [ ] 마감 3일 이내 건에 임박 표기가 있고, 마감 시각이 원문에 있으면 적혀 있다
- [ ] B그룹 각 건에 트리거 문장이 있다. C그룹 각 건에 재서술 문장과 리스크가 있다
- [ ] 부재 확인·우선순위 액션·한계 고지 섹션이 있다
- [ ] diff 모드면 직전 보고서 링크와 미갱신 소스 명시가 있다
- [ ] 큐의 열린 `verify` 항목이 남아 있지 않다 (남아 있으면 검증 누락 또는 `manual`로 재분류 필요)
