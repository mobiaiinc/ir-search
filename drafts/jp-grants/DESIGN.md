# jp-grants — 일본 공모·보조금·지자체·AI 지원사업 전수조사 → 応募 설계 초안

> 초안. 소스 URL·API·제도 수치(상한액·요건)는 기억에 의존한 것이며 **실측 검증 전**이다. 応募 서류는 초안까지이고 **제출은 사람이 한다.**

## 무엇을 하는 스킬인가

일본 정부(経産省·中小機構·NEDO·IPA·総務省 등)·자치체(都道府県·市区町村·外郭団体)의 **公募·補助金·助成金·委託事業·実証事業** 모집 공고를 전수 수집하고, 신청자 프로필(법인 형태·소재지·규모·업종·gBizID 유무)로 자격을 公募要領 원문에서 검증해 A/B/C로 분류한 뒤, **A그룹 중 사용자가 고른 건에 대해 応募 서류 초안(事業計画書·申請書 항목별 문안)을 만든다.** 상태는 `.jp-grants/`에 남긴다.

ir-search와 같은 뼈대에 두 단계가 붙는다: **5단계 応募 패키지 초안**, **6단계 제출 체크리스트**(gBizID·電子申請 화면·締切 시각·添付 서식). 자동 제출은 하지 않는다 — jGrants는 gBizID 로그인이 필요하고, 우회하지 않는다는 원칙이 그대로다.

## 일본 특유의 축 (ir-search와 다른 것)

| 축 | 왜 중요한가 | 프로필 질문 |
|---|---|---|
| **法人格·所在地** | 대부분 補助金이 "国内に本店又は主たる事業所" 요건. 한국 법인은 일본 법인·지점 없이는 거의 불가 → **B그룹의 최대 트리거** | 일본 법인/지점 유무, 소재 都道府県·市区町村(자치체 사업은 시 단위로 갈린다) |
| **中小企業 定義** | 中小企業基本法 기준(업종별 資本金·従業員 상한)으로 대상이 갈린다. スタートアップ 사업은 창업 N년 이내 조건 | 資本金, 従業員数, 業種, 設立年 |
| **gBizID プライム** | jGrants 전자신청의 전제. 발급에 시간이 걸린다(우편 심사 1~2주로 기억, 마이넘버카드 온라인은 즉시로 기억 — 확인 필요) | gBizID 등급(なし/エントリー/プライム) |
| **認定経営革新等支援機関** | 一部 보조금(事業再構築 계열 등)은 支援機関 확인서 필수 → 외부 파트너 필요 | 거래 중인 支援機関(税理士·金融機関) 유무 |
| **AI 관련 사업** | 経産省 GENIAC(基盤モデル), IPA·NEDO AI 공모, 자치체의 DX·AI導入 支援, 東京都 디지털 도구 도입 지원 등 — 이름에 AI가 없는 "DX", "生産性向上", "省力化"가 실제 대상 | 아이템 한 줄(일본어 재서술 각도의 재료) |
| **締切 시각과 방식** | 電子申請 17:00 마감이 흔함, 우편 必着/消印 구분, 事前エントリー 마감이 본 마감보다 앞선 사업 | — (검증 항목) |

## 프로필 축 (`.jp-grants/profile.md`)

- 対象: 프로젝트명 (아이템 한 줄, 일본어 병기)
- 法人: 日本法人 / 日本支店 / 韓国法人のみ(日本拠点なし) / 個人事業主(日本)
- 所在地: 都道府県·市区町村 (없으면 "拠点なし"; 설립 예정지)
- 規模: 資本金 / 従業員数 / 設立年 / 業種(日本標準産業分類 대분류)
- 代表者: 年齢帯 / 性別 / 在留資格(外国人創業의 경우 経営・管理 등) — **필요한 축만**, 그 외 개인정보 금지
- 必要なもの: 補助金(設備·開発) / 助成金(人件費·家賃) / 実証フィールド / 入居·拠点 / 海外展開 / AI·DX導入
- gBizID: なし / エントリー / プライム · 認定支援機関: あり/なし
- 소스 구성 / 마지막 조사 (스크립트 관리)

## 레코드 스키마

```json
{"source": "jgrants", "id": "a0W…", "title": "令和8年度 …補助金", "org": "経済産業省 / 中小企業庁", "region": "全国|東京都|…",
 "field": "設備投資|AI・DX|創業|海外展開|…", "target": "中小企業|スタートアップ|個人事業主|…",
 "apply_start": "2026-09-01", "apply_end": "2026-10-15", "apply_end_time": "17:00", "max_amount": "1,000万円", "rate": "1/2",
 "method": "電子申請(jGrants)|郵送|メール", "url": "https://…"}
```

`max_amount`·`rate`는 목록에 있을 때만(jGrants 검색 결과에 있음으로 기억). 없으면 빈 값 — 3단계에서 채운다.

## 워크플로

```
0 status → profile (일본 축 질문 한 번에)
1 수집: jgrants(전국 + 소재지) → jnet21 → mirasapo → 省庁별 → 자치체(소재지) ; --drop-expired
2 검토: 제목·対象·地域·締切 전수 읽기 → 후보 verify 큐 (일본어 재서술 각도 포함: "AI"가 아니라 "DX·省力化·生産性向上")
3 검증: 公募要領 PDF/HTML에서 対象者·所在地要件·補助率·上限·対象経費·除外·締切(時刻·方式)·必要書類·gBizID·支援機関 — 근거 인용
        15건 이상 → jp-grant-verifier (추출만)
4 판정: A 即応募可 / B 要件充足後(法人設立·gBizID取得·支援機関確保) / C リフレーミング → report.md
5 応募 패키지 초안 (사용자가 고른 A건마다): 公募要領의 審査項目 순서대로 事業計画書 문안, 申請書 항목별 값, 添付 목록, 経費 내역 틀 → runs/<날짜>/apply/<id>/
6 제출 체크리스트: gBizID 등급 확인, 事前エントリー, 締切 시각(JST), 방식, 서식 버전, 支援機関 확인서 → queue(apply, deadline)
마무리: jp-report-reviewer 검수 → queue → run finish → status
```

## A / B / C 정의

| 등급 | 조건 | 반드시 적을 것 |
|---|---|---|
| A 即応募可 | 法人格·所在地·規模·業種 요건을 프로필 그대로 충족, 除外 미해당, 締切 미경과, **gBizID 요구 시 프라임 보유** | 근거 인용, 上限·補助率, 締切 日時·方式, 必要書類, URL |
| B 要件充足後 | 트리거가 公募要領에 명시: 日本法人設立 / 事業所設置 / gBizIDプライム取得(발급 소요 포함) / 認定支援機関 확보 / 創業N年 | 트리거 문장, 소요 기간(공식 안내에 있으면), 연쇄(法人設立 → gBizID → 応募) |
| C リフレーミング | 対象者는 맞지만 취지가 다름 → 아이템을 그 사업의 언어(DX, 省力化, 地域課題, 観光, 介護 등)로 재서술한 **일본어 문장** + 리스크 | 재서술 문장, 리스크(成果指標, 実績報告 부담) |
| 제외 | 위 셋 아님 | 유명 제도(ものづくり·IT導入·持続化 등)는 "検討したが除外"에 이유+URL |

불명 규칙 동일: 요령에 없으면 不明, 문의처(問合せ先·事務局 전화·메일) 병기. A인데 不明이 있으면 A 유지 + "要確認".

## 5단계 — 応募 패키지 초안의 경계

- 입력은 **프로필 + 公募要領 원문 + 사용자 프로젝트 폴더의 자료(README·사업계획·기술 문서)** 뿐. 실적·매출·고용 수치는 사용자가 준 것만 쓰고, 없으면 `[要記入]` 플레이스홀더
- 審査項目(加点項目 포함)을 요령에서 뽑아 항목마다 "요령의 문장 → 우리 문안 → 근거 자료" 3열로 만든다
- 서식(様式)이 Word/Excel이면 문안만 md로 만들고 사용자가 옮긴다. 서식 자동 채움은 2차 범위
- **제출하지 않는다.** jGrants·메일·우편 모두 사람이. 스킬은 체크리스트와 締切 큐까지
- 개인정보(마이넘버·통장·인감)는 다루지 않는다. 필요 서류 목록에 이름만

## 워크스페이스 `.jp-grants/`

`.ir-search/`와 같은 다섯 파일. 다른 점: 큐 `type`에 `apply`가 **締切 시각**과 방식을 `note`에 갖는다(`17:00 JST · jGrants`), `runs/<날짜>/apply/<id>/`가 応募 패키지 초안 폴더로 추가된다. `profile.md`는 일본어 병기 허용.

## 스크립트 (전부 미작성)

| 파일 | 역할 | 출처 |
|---|---|---|
| `fetchlib.py` | 그대로 | ir-search |
| `jgrants_crawl.py` | 공개 검색 API(키워드·地域·受付中) `list` / 상세 `detail` | 신규 |
| `sources_crawl.py` | `page_jnet21`, `page_mirasapo`, `page_meti`, `page_nedo`, `page_ipa`, `page_tokyo_kosha`… | ir-search 패턴 |
| `diff_surveys.py` | 그대로 (`apply_end` 동일 필드명) | ir-search |
| `survey_state.py` | 그대로 + 워크스페이스명 | ir-search |

PDF(公募要領)가 표준이므로 텍스트 추출 의존성(선택)이 stock-search와 공통 과제.

## 함정 (예상, 실측 필요)

- 公募要領이 PDF 첨부만이고 목록에는 제목·締切뿐 — 3단계 비용이 ir-search보다 크다
- 자치체 사업은 "市内に事業所" 요건이 흔하고, 시 사이트에만 올라온다 — 소재지 없이는 커버 불가 → 프로필에서 소재지를 반드시 받는다
- 事前エントリー·説明会 참가가 応募 조건인 사업이 있다 (締切 두 개)
- 회계연도(4월 시작) 기준으로 "令和8年度" 표기 — 서기 변환을 파서에서
- 外国法人·外資 비율 제한이 있는 사업(안보·補助金適正化法 관련) — 요령에서 확인, 없으면 不明
- gBizID プライム 발급 지연이 締切을 넘기는 경우 — B그룹 트리거의 소요 기간을 반드시 적는다
